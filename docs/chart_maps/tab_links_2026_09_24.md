# ⌘-click a Chart Maps tab → that section in a new browser tab (2026-09-24)

Ajay 2026-09-24: *"add Command clicks to the Tabs in chart maps so I can open
new tabs.. Of that specific Section"*.

## What was wrong

Every tab in the strip was a `<button>`. A button has no address, so ⌘-click,
middle-click and right-click → "Open in new tab" all did nothing — there was
nothing to open. The address already existed: every tab lives in the URL as
`?tab=…`. The strip just never handed it out.

## What changed

Each tab is now an `<a role="tab">` whose `href` is its own section:

* **Plain click** → unchanged. `preventDefault()` and switch in place with
  `replace: true` history, no reload.
* **⌘-click / Ctrl-click / ⇧-click / middle-click / right-click → Open in new
  tab** → left to the browser, which opens the `href`.

`isPlainLeftClick` (`frontend/src/lib/chartMaps.ts`) decides which click is the
strip's: button 0 with no ⌘, Ctrl, ⇧ or ⌥. Every other click is the browser's.
Intercepting any of them is how a link ends up behaving like a button again.

## One address for both clicks

`tabSearch(params, t)` builds the query a tab lives at — the current params with
`tab` set and `pattern` dropped. **Both** `setTab` (the in-place switch) and the
tab's `href` call it, so a plain click and a ⌘-click can never land on two
different boards. Everything else in the URL rides along — `symbol`, `window`,
`days`, `sort` — so the new browser tab opens the section set up the way this
one is. `pattern` is dropped exactly as `setTab` always dropped it: it names a
pattern inside Past Winners and means nothing elsewhere.

The `href` is **relative** (`?tab=…`): it resolves against the page it is on,
so no router basename can make it point somewhere else.

## Unchanged

No tab moved or was renamed; no board changed. The tab-open counter
(`chart-maps:tab:<tab>` in `usage_stats`, which drives the most-used-first
order) runs in an effect on the *landed* tab, so a tab opened by ⌘-click still
counts. The look is unchanged: `.cm-tab` gains `display: inline-block;
text-decoration: none` so the anchor renders exactly like the button did, plus a
`:focus-visible` outline.

* `frontend/src/lib/chartMaps.tabLinks.test.ts` (12) — `tabSearch` sets the tab,
  keeps the rest, drops `pattern`, never mutates its input, replaces rather than
  appends; `isPlainLeftClick` for a plain click and six negatives (⌘, Ctrl, ⇧,
  ⌥, middle, secondary).
* `frontend/src/pages/ChartMaps.test.tsx` (+8) — every tab is an `<a>` with its
  own href; the href keeps this page's symbol/window; a plain click is
  default-prevented and switches in place; ⌘ / Ctrl / ⇧ / middle clicks are
  **not** default-prevented and leave this tab where it was; no href carries
  `pattern`.
* A frontend contract pins the `<a role="tab">` strip, the shared `tabSearch`,
  and the modifier hand-back — mutation-checked (a `<button>` fails it).
