## What ships (backend)

| piece | file | what it does |
|---|---|---|
| read builder | `backend/chart_maps/gex_read.py` | the ONLY builder of the tile block `gex`: chips, one shared title, sort keys, for both the nightly and the live read |
| board attach | `backend/chart_maps/board.py` `attach_gex` | the nightly read on EVERY tile of every tab, LAST in `board()`, in its own try |
| coverage record | `backend/chart_maps/gex_seen.py` | every `board()` call adds the served symbols to Mongo `chart_maps_seen` (one doc per ET date × tab); the five chart-card tabs are recorded by `POST /chart-maps/gex-live` instead |
| live read | `POST /chart-maps/gex-live` (`backend/chart_maps/api.py`) | one batched call per tab open; returns the live read beside the nightly one |
| nightly sweep | `backend/options/gex_history.py` `run()` | the 17:50 ET cron now also sweeps the Chart Maps names; each row is tagged `universe` |
| strength bias script | `backend/scripts/gex_strength_by_expiry.py` | re-runnable measurement of the near-expiry bias quoted below |

The engine is unchanged: `options.opex.compute_opex` reads the chain, `options.gex_history.slim_row` shapes it, and
`options.gex_history.board_bucket` buckets it, the same read the GEX Board page uses.

## The payload (BE ⇄ FE contract)

`GexRead` (one read, nightly or live):

```
{ "kind": "nightly" | "live",
  "bucket": "bullish" | "bearish" | "mixed" | null,   // null IFF void != null
  "void": null | "settled" | "no_gamma",              // non-null = counts as no read
  "regime": "pinning" | "amplifying" | null,
  "spot", "flip_strike", "put_wall", "call_wall", "net_gex_dollars": number|null,
  "adv_dollars_50": number|null,
  "strength": number|null,            // SIGNED net/adv; null when void or either side null
  "expiration_date": "YYYY-MM-DD"|null,
  "days_to_expiry": int|null,         // calendar days from the read's date
  "reliability": "index" | "single_name" | null,
  "as_of": "YYYY-MM-DD" (nightly date_et) | ISO-8601 UTC (live, the read's own time),
  "as_of_text": "Fri 9/25 close" | "live 10:42 ET" }
```

`GexChip`: `{ kind: "single"|"close"|"now"|"none", text, tone: "good"|"warn"|"muted", title }`. Every chip of a tile
carries the same full title.

`GexTileRead`: the tile's `gex` key, and each row of the live answer. Both have the same shape:

```
{ "symbol", "live_status": "not_asked"|"ok"|"no_options"|"pending"|"failed"|"market_closed",
  "nightly": GexRead|null, "live": GexRead|null,   // live non-null IFF live_status == "ok"
  "chips": GexChip[1..2], "sort": { "group": 0|1|2|3, "key": number|null, "source": "live"|"nightly"|null } }
```

Board payload keys (every tab): `tiles[i].gex`, `gex_rule`, `gex_legend`, `gex_scope`, `gex_sort_off` (null except
`zero_dte`), `gex_counts {bullish, mixed, bearish, none}`, `gex_as_of`, `gex_note`.

`POST /chart-maps/gex-live` body `{symbols: [...], tab?: string, repoll?: bool}` returns 422 on an empty list and
200 otherwise with `{as_of, as_of_text, session, market_closed, rows{SYM: GexTileRead}, pending, counts, legend,
scope, sort_off, ttl_sec, budget_sec, truncated, rule, note}`. An unknown `tab` is treated as none.

## Chips and order

| chip | when | group |
|---|---|---|
| `🧲 GEX bullish · 0.42%` | dealers net LONG gamma (pinning) and spot at/above the flip | 0 |
| `🧲 GEX mixed` | regime and flip disagree | 1 |
| `🧲 GEX bearish · 1.3%` | dealers net SHORT gamma (amplifying) and spot under the flip | 2 |
| `🧲 no GEX read` | no ledger row within `NIGHTLY_MAX_AGE_DAYS`, a settled chain, or no gamma | 3 |
| `🧲 no options read` | the live read got no chain (no listed options, **or the request was refused**; Massive's page-1 refusal looks the same) | 3 |
| `🧲 close: bullish` + `🧲 now: bearish` | the last close and the live read disagree | the live group |

The sort uses the live read when it is usable, otherwise the nightly one. Inside groups 0 and 2 it runs by `key`
descending: strongest bullish first, then **weakest** bearish first, so the page reads as one bullish→bearish
gradient. Mixed and no read keep the tab's own order. The FE sorts; the backend never reorders a tile.

## Strength: "GEX vs the stock's size"

`strength = net_gex_dollars ÷ ADV50`, signed. `net_gex_dollars` is the dealer hedging per 1% move. ADV50 is
`sepa.adr.liquidity_check` (default `period` 50) over CLOSED bars: any bar dated today is dropped first
(`supply_demand.zone_store.drop_today`). With under 50 closed bars, zero volume or a non-finite value there is no
strength (null). It shows as a % of the average day, 2 decimals under 1% (`0.19%`) and 1 above (`3.0%`). Across the
175 latest ledger rows the scale was median |ratio| 0.19%, p10 0.012%, p90 1.18%.

**Near-expiry bias, disclosed on every tile title.** A chain whose nearest expiry is a day out reads stronger. From
`scripts/gex_strength_by_expiry.py`, re-run 2026-09-27 18:13 UTC over 35 ledger days since 2026-08-01 with settled
rows excluded:

| nearest expiry | median \|net ÷ ADV50\| | n |
|---|---|---|
| ≤1 day out | 0.301% | 567 |
| ≥2 days out | 0.172% | 5,204 |

Ratio **1.74×**. Row bootstrap CI95 is **[1.39, 2.08]**; the symbol-clustered bootstrap CI95 (933 symbols) is
**[1.38, 2.10]**. So "strongest bullish" partly means "expiry tomorrow". The tile title says so, and whether to
adjust for it is his call (H21). This measures a bias in the ranking key only. It is not a forward test, so it has no
placebo.

## Settled expiry chains = no read

`compute_opex` reads the NEAREST expiry in Massive's snapshot, and after the 16:00 close that snapshot still lists a
contract on its own expiry date. A 17:50 ET row on an expiry day therefore describes a dealer book that no longer
exists. `gex_read.settled()` marks a read **settled** in two cases:

- its expiry is before the read's date, or
- its expiry is on the read's date and the read was taken after the close (`sepa.prices.trade_session` says
  `afterhours` or `closed`).

A legacy row with no `recorded_at` on its expiry date also counts as settled. A settled read is **no read** (group 3),
and the title says which expiry settled. A live read in regular hours on an expiry day is NOT settled. When the live
read is settled and the nightly one is usable, the nightly read carries the tile.

**Settled since it was read (fix 2026-09-27).** The same rule also runs against the moment the read is SHOWN:
`read_block(..., now_et=…)` voids a read when `settled(expiry, now_et, now_et's date)` holds, for nightly and live
reads alike (`nightly_blocks` and `live_payload` both pass the clock). Before this, a Thursday row on a Friday expiry
still ranked as bullish all weekend, and on Friday after 16:00 it carried the tile when the live read settled (9 of
63 usable reads in the live run, LUNR first on Under Value). Now it reads no read from Friday 16:00 on. A cached live
read taken 15:55 on its expiry day and served after 16:00 is also void. Side effect, conservative: between 00:00 and
04:00 ET on an expiry day `trade_session` says `closed`, so a row on that day's expiry also reads no read in that
window (no read, never a wrong one). Tests: `test_thursday_row_on_friday_expiry_is_no_read_on_saturday`,
`test_thursday_row_is_no_read_friday_after_close_even_when_live_settles`,
`test_thursday_row_still_reads_before_friday_close`, `test_cached_live_read_on_expiry_day_voids_once_served_after_close`.

Ledger counts of settled rows / all rows on the day (same script): 2026-09-18 (monthly) **188/188**; 2026-08-21
**194/194**; 2026-09-25 47/175; 2026-09-11 45/173; 2026-09-04 39/171; 2026-08-14 42/195; other days 1–8 (index ETF
weeklies). On a monthly-expiry weekend the whole board reads "no read" until Monday's live read. That is the
honest default. Skipping the settled expiry inside `compute_opex` is not done, because it would change the GEX Board,
the push context line and the Desk report (H19).

A read whose regime is missing (no spot or no greeks) is `void: "no_gamma"` and also counts as no read. It is never
shown as "mixed".

## Live read (just in time)

- It is one batched `POST /chart-maps/gex-live` for the shown tiles, at most `board.LIMIT_MAX` (80); any extra are
  counted in `truncated`.
- It uses its own `ThreadPoolExecutor` (`gex_history.SWEEP_WORKERS` = 8 workers), never the event loop's default
  executor that `board()` shares. It waits `board.TAPE_BUDGET_SEC` (25 s). Anything unfinished answers `pending` and
  lands on the next request.
- Single flight: one `compute_opex` per symbol at a time. The done-callback is registered AFTER the lock is released,
  because on an already-finished future it runs on the calling thread, and under the lock it would deadlock (pinned
  by `test_claim_never_deadlocks_on_instant_compute`).
- The cache TTL is `options.zero_dte.CACHE_TTL_SEC` (60 s). `ok` and `no_options` are cached; a `failed` read never
  is. `repoll: true` (the page's pending re-polls only) serves any same-ET-day entry whatever its age and submits only
  names with no entry and nothing in flight. The entry's own time is its `as_of_text`.
- When the market is closed there is no Massive call and every row is `market_closed`. That covers weekends and NYSE
  holidays (`market_hours.gate.closed_reason`) and `overnight` (`trade_session` = `closed` on a trading day, i.e.
  before 04:00 or after 20:00 ET).
- **The live read is NEVER written to `gex_history`.** It uses `slim_row` (pure) and nothing else. The ledger stays
  the post-close book that the alert context line, the Desk report and the GEX Board read. A source guard pins that
  `gex_read.py` contains none of `update_one|insert_one|insert_many|replace_one|bulk_write|add_symbol|gex_history.run|.run(`.

## Coverage: "Only Chart Maps names nightly"

- `gex_seen.record(tab, symbols)` runs after every `board()` call, in its own try. One atomic aggregation-pipeline
  update on `chart_maps_seen` `_id="YYYY-MM-DD:tab"` (upsert) moves the served names to the END of `symbols` (drops
  them where they were, appends them), so `symbols` is ordered by LAST SEEN, oldest first, with no duplicates. No
  pruning (≤16 docs a day). Fix 2026-09-27: it used `$addToSet`, which keeps first-seen order, so once a tab's day
  passed 80 names the cap kept the day's EARLIEST 80 and dropped the names on screen at the close (demo: 80 names at
  08:00 + 20 new at 15:55 → 0 of the 20 swept). The pipeline was checked on Mongo 7.0 with a read-only `$documents`
  aggregation. Test: `test_names_on_screen_at_the_close_survive_the_cap`.
- `gex_seen.recent_symbols()` covers the last `gex_history.NIGHTLY_MAX_AGE_DAYS` (7) ET days. Within each tab it takes
  the newest date first and, inside a day, the most recently seen name first (the stored list read back to front),
  deduped, and keeps **at most `board.LIMIT_MAX` (80) per tab**. It then takes
  the union across tabs in `gex_seen.seen_tabs()` order — `board.TABS` (16), then the five chart-card tabs
  (`gex_seen.CARD_TABS`, below) — so the total is ≤ 80 × 21 = 1,680 (it was ≤ 1,280 before the card tabs joined).
  There is no global cut, so no tab (zones is alphabetically last) is ever cut for its name.
- `gex_history.universe_split()` returns `(core, extra)`. `core` is the classic universe, still capped at
  `MAX_UNIVERSE` 200. `extra` is the Chart Maps names minus core. `snapshot_universe(include_chart_maps=False)`
  (the default) is unchanged for every existing caller.
- `run(include_chart_maps=True)` is the cron default. It tags each row `universe: "core" | "chart_maps"` and returns
  `core` / `chart_maps` counts. The GEX Board's refresh button calls `run(include_chart_maps=False)` because it runs
  behind a request and Cloudflare times out at about 100 s.
- **The crontab line is unchanged** (`50 17 * * 1-5 … options.gex_history`). The code reaches cron only when the
  `cron` service is deployed: **deploy `api cron frontend`**. Expected runtime is about 175 + 600–1,100 names, roughly
  2–3.5 min at 8 workers (it was 30 s).
- Failure modes:
  - A tab not opened for 7 days has no nightly rows for its names.
  - The first night after deploy covers only the names served since deploy.
  - A failed `record` means those names miss the sweep; the board itself is unaffected.
  - `premarket_entry`'s 15-minute `board()` calls keep zones and deep_demand covered.

## Index

`gex_history.INDEX = [("symbol", 1), ("date_et", -1)]`, named `symbol_date`. `ensure_index()` follows the
`zone_edge.ensure_track_index` pattern: it is idempotent, and a fake without `create_index` is fine. It runs at the
top of `run()` and once per process from `snapshot_for` (the `_INDEXED` flag is set only on success). It serves
`snapshot_for`'s `$match`/`$sort` and `series()`. Before this, the collection had only `_id` and every board load
did a COLLSCAN.
