## Two groups, one `sort=` toggle (the 🏎️ Dual Momentum pattern)

| group | served key | who | order |
|---|---|---|---|
| 🏔️ At ATH | `default` | print through the prior closed high, or `>= AT_ATH_TOL x` the live high | % vs the PRIOR closed high, descending (through-today first), symbol |
| ↘️ Slipping | `slipping` | an all-time or 52-week high set today or in the last `SLIP_LOOKBACK_SESSIONS` closed sessions, print `< AT_ATH_TOL x` that high | freshest high first, smallest drop, symbol |

`slipping` is tab-scoped (`board()` coercion, the `nearest_demand` precedent): an unknown sort → 🏔️; `slipping` on any
other tab → the default. `out["sorts"]` is exactly the two labelled entries.

Constants (`chart_maps/ath_tab.py`) — every number imported or named, never typed in a sentence:

| name | value | source |
|---|---|---|
| `AT_ATH_TOL` | `zone_edge.NEW_HIGH_TOL` (0.98 → "within 2%") | the app's "at the 52w high" constant — HIS CALL #1 |
| `BAND_PCT` | built from `AT_ATH_TOL` | every sentence prints it |
| `SLIP_LOOKBACK_SESSIONS` | 21 | the lid-break "does not hold" window — HIS CALL #2 |
| `SMA_DAYS` | 50 | `entry_exit._sma` |
| `MEMO_TTL_SEC` | 3600 | cache freshness, not a rule |
| 52-week high | `key_levels.period_levels(..., ("year",))` | `YEAR_BARS = 252`, omitted below it |

Counts invariant (pinned by `test_09_counts_invariant_and_orders`):
`scanned == at_ath + slipping + at_52w_only + rest + stale + no_print + no_bars`.
Sub-counts: `at_ath_proven`, `through_today`, `slip_from_ath` (a PROVEN all-time high only),
`slip_from_high_since` (the high since the first bar, not proven), `slip_from_52w`, `slip_above_sma50`,
`history_pending`, `history_short`, `split_refetch`. Both served headers state proven all-time and "high since"
counts apart; neither calls a group total "all-time" (critic 2026-09-29 #1).

## Data plan — why a new store

- The shared daily cache holds **2 years**. Asking the shared loader for `max` with a forced refetch would overwrite
  the one shared doc app-wide (every scan, zone and chart would then read a 10-year frame) and is still only 10 years.
  **Never done here** — a source-grep test and the contracts guard it.
- NEW collection **`ath_history`** (`chart_maps/ath_history.py`, the only writer): ONE summary doc per symbol from ONE
  Massive **monthly** aggregates call (`prices._fetch_massive(..., timespan="month", start="1970-01-01",
  end=<last complete month>)`; the default day call is byte-identical, pinned). Massive's floor on our plan is
  **2003-09**.
- Two cuts before a bar counts:
  1. `prices._cut_foreign_head` — the curated FIRST_SESSION / rename cut the whole app applies.
  2. `last_hole_cut` — a calendar month with no print between two prints = the ticker went dark; bars before the LAST
     such hole belong to an earlier listing and are cut (DJT, PCOR, RKT, OGN, HCA, PFGC probed). HIS CALL #7.
  A recycled ticker with neither a curated cut nor a gap is NOT cut; it is only refused "all-time" when its bars
  reach back before the listing date (`bars_before_listing`).
- The read (`closed_read`) = max(doc high, the 2-year CLOSED daily frame's high) plus today's snapshot high
  (`rth`/`close` phases only). A recent high gets its exact day from the frame; an older one reads as a month.
- **Split guard.** The doc stores its last month's high (`check_month`/`check_high`); when the frame's high in that
  month differs by more than half a cent the doc is ignored (frame-only, `history_split`) and a refetch is asked no
  sooner than `REFETCH_MIN_AGE_SEC = prices.CACHE_TTL_SEC`. A good doc whose `check_month` is OLDER than the rolling
  frame's first bar month is refetched (`needs_fetch(..., frame_first=)` → `"check_stale"`, served frame-only
  meanwhile), so the check can never pass on an empty overlap (critic 2026-09-29 #5).
- **Honesty.** "ATH" only when the history reaches the listing (`completeness`: first bar within
  `ipo.BAR_SLACK_DAYS` of `symbols.first_session`, else the profile listing date; a monthly first bar may start on
  the listing month's first day). Otherwise the label is `High since <first bar>`, the badge ends
  "— not proven all-time", and the name is counted. **Never proven from the 2-year daily frame alone** (critic
  2026-09-29 #4): proof needs the stored monthly doc read and good AND `monthly_reaches_listing` — the doc's first
  monthly bar within the listing window, or, for a curated `FIRST_SESSION` only, the month right after the listing
  month (`_cut_foreign_head` drops the listing month's own monthly bar, stamped the 1st, by construction; SPCX
  2026-06-12). A young or 2-year-old listing whose history is still pending reads "high since" until the fill lands.
- **Fill.** `ath_history.fill` — sequential, `FILL_PAUSE_SEC` between calls, never on a request. The tab's background
  build hands missing / curation-changed / week-old-empty / split names to ONE module-wide filler thread; the memo is
  invalidated every `FILL_REBUILD_EVERY` names and at the end. A transport failure writes nothing and waits for the
  next session's pass (so a provider with nothing never loops a rebuild). `ATH_HISTORY_STORE=memory` keeps everything
  in-process (branch verification: no prod writes). Manual run:
  `python -m chart_maps.ath_history --fill [--limit N]`.

## Payload

- `board.tab == "ath"`, `board.sort ∈ {"default","slipping"}`, `board.sorts` = the two entries.
- `board.ath_board = {state, session, phase, group, counts, header, note, built_at, measured:false, band_pct,
  lookback_sessions, history:{read, pending, filling}}`.
- `board.note` = the UNMEASURED note, or the group's empty sentence when no tile survives.
- `tile.ath = {group, proven, status, label, since, listed, high, high_date, high_date_is_month, high_today,
  pct_from_high, through_prior_pct, w52:{price,date,today}|null, pct_from_52w, sma50, above_sma50, px, basis, tape,
  slip:{from,price,date,sessions_ago,pct}|null, text}`; `text == badges[0].text`.
- One `neutral` line: the reference high only (an old far-away ATH never squashes a chart). 🎯 enterable n/a (absent
  from `KIND_BY_TAB`, HIS CALL #8).
