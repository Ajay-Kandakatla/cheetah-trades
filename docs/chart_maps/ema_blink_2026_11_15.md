## The definition (ONE engine)

`backend/chart_maps/gajjala/ema_cross.py` `blink_read(ema_fast, ema_slow, ts, closes, …)` reads the LATEST bar where both
EMAs are finite on the frame the card DRAWS (its own stored 9 / 21 curves — no second EMA; a daily tile goes through
`blink_from_bars`, the `crosses()` prologue over `bars._masked_ema`).

| state | rule | tier (fastest first) | closeness |
|---|---|---|---|
| `crossed_up` | the 9 is over the 21 now AND a 9-over-21 cross is on the frame | `fresh` (cross on this bar) · `up` (older) | bars since the cross |
| `closing_in` | the 9 is under (or touching) the 21, the gap narrower than `BLINK_NARROW_BARS` bars ago, the straight-line projection ≤ `BLINK_MAX_BARS` bars | `imminent` (≤ 1 bar; a gap of exactly 0 = imminent, closeness 1) · `near` (≤ `BLINK_NEAR_BARS`) · `closing` | projected bars to the cross |
| `none` | anything else — incl. the 9 over the 21 the whole frame with no cross on it (`above: true`) | — | — |

ONE axis: `TIERS = (fresh, imminent, near, closing, up)` = blink speed = sort rank = the tab dot's pick.
`bars_to_cross = max(1, ceil(−gap / rate))`, `rate = (gap − gap[i−L]) / L`; the quotient is rounded to 9 decimals before
the ceiling (float hygiene only — the stored EMAs carry 6 decimals, so 0.4 / 0.2 reads 2, not 3).

## The tab dot — what `n` means

`n` = **the number of SYMBOLS in the tab's store for its session that have at least one card at or near the cross on the
tab's PRIMARY frame — cards past the board's cut included, the 15-minute toggle excluded.** Not "the tiles on screen".

Per tab ONE projected Mongo find (stamps only: `tile.bars{m}.t`, the curves and the 🎾 `_prior` twins; no closes, no
`$slice`) + THE frame builder `tab._tile_frame(doc, primary, variant, wide=setup == "reversal_squeeze")`. A GG card = a
read in a `tab.TILE_STATES` state that `tab._vcp_listed` cards (the board's own rule). Every 🧠 card is such a read
(`potential.potential_kind` requires `state == GC.POTENTIAL_STATE` = "forming" ∈ `TILE_STATES`), so the 🧠 cards are
counted without reading the tracker; a tracker row whose read is no longer in a card state has no card and is NOT counted.
**2026-11-15 note — deviation from spec §3.8 (C4a), HIS call:** the spec unions `st.potentials(session)` into the
card set; the count does not read the tracker (reason above — pinned by
`test_tab_counts_C4a_a_potential_card_counts_through_its_forming_read_and_the_tracker_is_never_read` and its
NEGATIVE). Reading the tracker too would only add a 🧠 row whose read has left the card states — a card the board
does not draw. Say so if you want it read anyway.
🧪 = 🚩's object (same reads, same frame). 🥇 = any setup in `luk.tab.TILE_STATES`. 👀 = owner only (`gajjala_watch: null`
for anyone else), every frame of the watch's `FRAMES`. A failing tab → that tab `null`, never a 500.

Known divergences from a board on screen (not defects):
1. the 15-minute toggle — the card reads its 15m curves, the count its primary frame;
2. a board cut at `limit` — the count includes the hidden cards;
3. a card's `gap_pct` — the count carries none (no closes projected).
4. ➖ Horizontal Fade cards draw on the frame their read was taken on (`tile_tf`: the Fade reads 15-minute first), so a
   default ➖ card may be on 15m while the count reads its 5m frame (same class as #1).

## The daily live-bar rule (`ema_blink.daily_through`)

During RTH the daily boards' last bar is today's FORMING bar (`sepa.prices.with_today_bar`; pre-market a synthetic flat
bar). `daily_through(now)` = `None` (keep every bar) only when today is a market day and `now ≥ rth_close_time(today)`
(16:00 ET; 13:00 on a `HALF_DAYS` date — the house clock, nothing typed); otherwise yesterday's ISO date, so the engine's
`through` drops every bar stamped today. A raising calendar drops today (the safe side). With
`BLINK_DAILY_UP_MAX_BARS = 0` a daily board blinks crossed-up only when the cross bar IS the latest CLOSED bar.
