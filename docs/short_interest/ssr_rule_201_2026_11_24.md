## The rule (SEC, https://www.sec.gov/divisions/marketreg/rule201faq.htm)

| Fact | Source | Constant |
|---|---|---|
| A drop of 10% or more from the prior day's regular-hours close | 17 CFR 242.201(b)(1)(i) | `SSR_TRIGGER_DROP_PCT = 10` |
| Only trades in regular hours (09:30–16:00) count; a pre-market or after-hours drop never triggers | FAQ Q1.1, Q1.2, Q2.1 | `SSR_REGULAR_HOURS_ONLY = True` |
| In force for the rest of the day and the next trading day | 242.201(b)(1)(ii), FAQ Q2.1 | `SSR_FOLLOWING_TRADING_DAYS = 1` |
| It runs whenever a national best bid is disseminated — after-hours included | FAQ Q2.1 | the window ends at the extended close (`alerts._closes`: 20:00, 17:00 on a half day) |
| A new 10% drop on the next day re-triggers it | FAQ Q2.2 | `retriggered` |
| The listing market decides; the prior close is the listing market's | FAQ Q1.3, Q3.1 | official wins |
| No FAQ question on dividends, splits or corporate actions | re-read 2026-11-23 | no adjusted close is ever computed |

Exactly 10.0% is ON: `round(low, 6) <= round(prev × (1 − 10/100), 6)` (the 6-decimal rounding is float noise, not a rule).
NOT reused on purpose: `drop10_tab.THRESHOLD_PCT` is HIS number for a tab; a test pins that `ssr.py` never reads it.

## The computed read — `record_pass`, the ONE writer

Rides the Gajjala 5-minute pass (`Deps.ssr`). Zero outside calls, never a key of the pass's `out`, never reads `ssr_corp`.

1. Runs only when `drop10_tab.mode_for(now)` reads live or after-close for the pass's session, on a good snapshot.
2. Every snapshot row → `eval_row`: no prior close → `no_prior_close`; no day bar dated the session → `no_day_bar`;
   **stamp guard [C3]**: the minute stamp (else the last-trade stamp) must be at/after 09:30 ET of the session —
   a present pre-market minute stamp rules even when the last trade is later (`stale` counted as `stale_bar`);
   a ≥ 5× discontinuity (`prices._is_scale_glitch`) → `price_suspect`; else on / off.
3. **Followed names — the minute bars decide [C2]** (`judge_followed`):

| RTH minutes | A minute at/under the line | Snapshot | Result | Trigger doc |
|---|---|---|---|---|
| any | — | `no_prior_close` / `price_suspect` / no row | that unknown, by snapshot | none |
| ≥ 1 | yes | other | **on**, by minute (`at`, the minute's low) | upsert `basis: minute_bar` (un-voids, upgrades a snapshot doc; never the reverse) |
| ≥ 1 | no | on | **unknown / `bars_disagree`** | none; an existing snapshot doc gets `void` |
| ≥ 1 | no | off / `no_day_bar` | **off**, by minute | none |
| 0 | — | any | the snapshot as is | the snapshot rule below |

   Minutes are judged by their ET START stamp in `[09:30, rth_close_time)`, never by a `session` column.
4. **Whole market — snapshot triggers on regular-hours passes only**: a row on, not judged by minutes, no doc yet →
   `trig|<date>|<SYM>` `basis: snapshot`, `seen_at` = the pass time. After the close nothing new is written
   (FAQ 2.1; AKAN's day bar moved after 16:00).
5. `day|<date>` is MERGED: `last_ok_at`, counts and one `names.<SYM>` entry per followed name with its own `at`.
6. **Close pass [C5]**: the first good pass at/after `key_levels.close_confirm_at` (16:05; 13:05 on a half day)
   writes `judged|<date>` once — `off` (names proven off, space-joined) and `unjudged` (`bars_disagree`,
   `late_print`, `price_suspect`, `no_prior_close`, `no_day_bar`) — and sets `day.final` (never unset). An OFF proved
   here is sound on any day: a later print can only lower a day low.
   *2026-11-23:* `unjudged` is keyed by the dash field key (`_field_key`, the same as `names.<SYM>`): 60 of 13,282
   live snapshot keys hold a dot (warrants such as `FCRS.WS` → `FCRS-WS`); a key starting with `$` is not stored.
   The read looks the why up through the same key.
7. Returns `{rows, usable, new, upgraded, voided, followed, final, stale_bar, lo_under_minutes, disagree}` — the cron
   line's standing measurements of C3 and C2.

Clocks [C8]: `mode_for` reads after-hours until 20:00 on a half day while `alerts._closes` ends it at 17:00. The pass
runs on `mode_for` (a 17:30 half-day pass may still write, harmless); `window` / `in_play` expire on `_closes`.

Severability (2026-11-24 refix): `record_pass` never needs `ssr_lists` to run. It takes the collection name from
`ssr_lists.SSR_COLL` and, if that module cannot import, from `ssr.SSR_COLL_FALLBACK` (a test pins the two equal), so
a broken list module stops only the official half.

## The resolution (served read)

Per asked symbol (asked spelling, norm, alias keys) and per trigger day T in `in_play(now)`:

| Evidence for T | Rule |
|---|---|
| official ON | a list row dated T — a corporate action never voids it (TOPP, ITP split 11/23 and are on NYSE's list) |
| computed ON | a `trig` doc not `void` and not corp-void (a dividend OR a split on T). Corp actions unread → the doc stands, `corp_checked: false` |
| computed ON overruled [C1a] | no official row, both lists complete for T, `SSR_COMPUTED_UNTIL_LISTS_COMPLETE` → `unknown / computed_only` (nothing drawn) |
| covered (no trigger proven) | (1) both lists complete and not `computed_only`; (2) `day.final` and the name POSITIVELY in `judged.off`, no split; (3) today, not final, a fresh `off` names entry (≤ `SSR_STALE_PASSES × PASS_CADENCE_SEC`), no split |

A dividend voids only a computed ON (a lower adjusted close only lowers the line); a split voids both.

| State | Rule |
|---|---|
| on | any on-day; governed by the newest; `official` when that day has an official row; `retriggered` with two on-days |
| off | every in-play day covered — no item |
| unknown | the newest uncovered day's why: `unread` · `corp_action` · `computed_only` · final day: the unjudged why or `no_final_read` · today: the entry's why, `scan_stale`, `not_followed`, `awaiting_first_scan` · past day without a judged doc: `no_final_read` |

Conflict `official_on_computed_off`: official wins and the title says the house numbers (when a followed name's entry
holds them) and "the exchange's list decides".
