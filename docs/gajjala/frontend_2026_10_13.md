## Behaviour
- ONE fetch: `GET /chart-maps/gajjala?sub&tf&focus&sort` (credentials include, no-store). `sub` rides only when the URL
  has one — a push deep link `?tab=gajjala&focus=SYM` lets the server resolve the sub; the SERVED `sub` is written back
  with history `replace` and no second fetch. An unknown `sub` asks for `bull_flag`.
- Re-read every `session.refresh_sec` seconds (300 in the 04:00–20:00 window); 0 / absent = no timer.
- `trackFeature('chart-maps:tab:gajjala:<sub>')` on every sub change; the page already counts the tab open.

## Review fixes (2026-10-13)

- **Params at the tab border.** The tab reads `sub` / `tf` / `sort` with its own meanings, and `tabSearch` carried every
  param but `pattern` across a tab switch. Support `tf=15m` → Gajjala's drew his 5-minute setups on 15-minute bars; his
  `tf=5m` → Support opened on the 24-hour frame (`TF_ALIAS`); his `sort=change` reached Back in Demand. `tabSearch` now
  drops `GAJJALA_OWN_PARAMS` (= `GG_SUB_PARAM`, `GG_TF_PARAM`, `GG_SORT_PARAM`, imported) when the switch crosses INTO or
  OUT OF `gajjala`; a click on the tab already open keeps them, and switches between two other tabs are unchanged.
- **`focus` scrolls once.** The param stays in the URL and each served refresh hands a new `tiles` array, so the page
  jumped back to the focused tile every 5 minutes. The scroll is now once per focus value, the first time that tile has
  landed (a ref); the outline stays.
- **Blurb numbers pinned.** The contract now reads `STAY_LISTED_SESSIONS`, `NO_TRADE_AFTER_OPEN_MIN`, `PASS_CADENCE_SEC`,
  `PASS_OPEN_ET` and `PSY_LEVELS` from constants.py: the blurb must print each, and any of those numbers printed in the
  blurb or the ✨ entry must be the constant's. The stay is Ajay's number (`CHEETAH_DEFAULTS`; GG said "a couple of days",
  S9 1:17:32), so the blurb says "stays listed 2 sessions (Cheetah default, not his)" in its own sentence. The "20:00" end
  is not pinned: `PASS_CLOSE_ET` is 20:05 (it admits the pass that closes the 19:55 bar).
- **No-pass boards.** The payload test waits on the board landing (`.gg-board[data-state="loaded"]`), never on the strip
  text, which is null when no pass has run. The fixture carries `no_pass_boards`: two REAL `tab.build` payloads with an
  empty store (closed day, before the first pass) — no strip text, no as-of, the served `empty_note`, no timer.
