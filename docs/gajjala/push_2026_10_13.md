## Shadow first (DECISIONS round A) (until 2026-10-16)

`constants.GAJJALA_PUSH_MODE = "shadow"`. The full gate runs every pass. Each A+ that would ring is:

- claimed under `SHADOW:GG:{date}|{SYM}|{setup}`. The prefix is `catalysts.medical.alerts.SHADOW_CLAIM_PREFIX`,
  imported, so there is one definition;
- stored in `gajjala_alerts` with `state: "shadow"`, `note: "shadow — not sent"` and the `would_push` payload;
- counted on the /alerts row as `shadow` (this pass) and `shadow_session` (today, counted from the ledger);
- **never sent.** The sender is not called. Tests check this on the alerts gate and on the full pass.

Only the exact string `"live"` sends. Any other value, including `"LIVE"`, `""` and `None`, runs as shadow, so a
bad value can never send by accident. Ajay flips the mode himself, after the WP6 250-session study has read.

Before it sends, a live claim checks the shadow key too. If the mode is flipped mid-session, nothing rings for an A+
the shadow pass already recorded that day.

## What rings (when live)

| Gate (in order) | Recorded as | Consumes the day's claim? |
|---|---|---|
| `variant` (long flag / near-kiss) or `grade` "B" on a read marked A+. WIDENED 2026-10-18 (DECISIONS13 D1): still refuses the near-kiss and "B"; a long flag no longer occurs (band empty while `K4_BF_LONG_FLAG_MAX` is None — 4–5 bar flags are A+ and ring) | `not_aplus_variant` | no |
| entry bar is not the latest closed bar **of its own frame** (`frames.as_of_bar_t[read.frame]`), or it closed more than `MAX_ENTRY_AGE_SEC` (= `PASS_CADENCE_SEC` + `BAR_SETTLE_SEC`, 330 s) before the pass | `late` (or `claimed_before` when the day's key already exists) | no |
| market closed today (`market_hours.gate.closed_reason`), checked before any claim | `suppressed_closed` | no |
| entry bar **started** before 09:30 ET | `suppressed_premarket` | no |
| entry bar started before 09:30 + `NO_TRADE_AFTER_OPEN_MIN` (09:45, derived) | `suppressed_first15` | no |
| entry bar closes after 20:00 ET (17:00 on a half day) | `suppressed_window` | no |
| `HALT_CALM_BARS` (OFF = None): entry bar closes within N bars of the halt's resume | `suppressed_halt` | no |
| `AH_EXHAUSTION_MAX_PCT` (OFF = None): after-hours A+, regular session above X% | `suppressed_exhausted` | no |
| `GG:` key, or its `SHADOW:` twin, already claimed today | `claimed_before` | — |
| send: sent > 0 / no device / raised or all failed | `pushed` / `no_target` / `failed` | yes |

- Windows: 09:45–16:00 and 16:00–20:00 ET, which run together as 09:45–20:00. Never 09:30–09:45 and never
  pre-market (HIS CALL 12). Half days follow `supply_demand.timeframes.HALF_DAYS`: 09:45–13:00 and 13:00–17:00.
- Per-frame latest bar: a ➖ Fade A+ on the 15-minute frame is judged against the latest 15-minute bar. At 10:21 the
  10:15 bar is the latest 15-minute bar, while the latest 5-minute bar is 10:20. Judged against the 5-minute bar it
  would read `late`. A test checks that it does not.
- The break (2026-10-13 review): the detectors count a break when the entry bar's HIGH trades above the trigger
  (`F.h[i] > trigger`, GG S8 "I'll enter right at the break"). The bar must have closed (closed bars only), but it
  may close back under the trigger. The Notifications text says exactly that. Requiring a close above the trigger
  is Ajay's call.
- Fresh, by the clock (2026-10-13 review): the frame check alone is not enough. `resample_ohlcv` drops empty
  buckets, so on a thin after-hours name the frame's own latest bar can be hours old. A 16:35 bar read by the 18:01
  pass is 86 minutes old and would have rung. An A+ rings only when `now − entry bar close ≤ MAX_ENTRY_AGE_SEC`. The
  minute-1 pass reads a bar ≈ 60–90 s old; the next pass sees it ≈ 6 minutes old, so a missed pass (host sleep,
  budget, a failed load) is `late`, never a stale push. A 15-minute bar stays the frame's latest for three passes;
  the 10:16 pass rings the 10:15 bar, and the 10:21 and 10:26 passes count `claimed_before`, not `late`.
- Once per (symbol, setup, ET trading day) (HIS CALL 11). A different setup on the same name rings separately.
- No digest. Five A+ in one pass make five single pushes, ordered by entry bar, then `SETUPS` order, then symbol.
  The kind is NOT in `push/recent.DIGEST_KINDS`.
- A refused A+ is recorded under `{key}#{state}`. It never uses up the day's claim, so a fresh A+ later the same day
  (for example after a pre-market A+) can still ring.

## The pass (`run.py`)

window (04:00–20:05 ET on a market day, else exit 0 with no snapshot call) → lease (`catalysts.medical.store.claim_lease`,
min gap `LEASE_MIN_GAP_SEC`) → snapshot → scan → split hold-out → `gajjala_scan` → after hours: carry replaced (good
snapshot only) → halts ledger → listed set → float steps 1–2 → 🎾 history (bounded) → frames (budgeted) → detectors →
Yahoo float step 3 + 🎾 re-read for changed floats → ☀️ pm levels / 🌙 K10 → `gajjala_reads` (with `stopped_today`) →
`alerts.run_pass` → pass doc + /alerts row → lease released.

A failed snapshot still reads the names already listed. The /alerts row then shows the reason "snapshot failed —
listed names read off the stored scan".

### Dry run (a throwaway container only — never `docker exec` into api/cron)

`python -m chart_maps.gajjala.run --dry-run --json [--now ISO] [--symbols A,B]`. A naive `--now` (no offset) is read as ET, the house rule (`prices.closed_daily_frame`): `--now 2026-10-13T10:16` replays 10:16 ET, not 06:16 ET. In a dry run:

- every collection is read normally, and every write is recorded instead of made;
- the sender and the /alerts row are recorders;
- the minute loader is `_fetch_massive_minute` + `_filter_sessions` (no `_mongo_put_day`);
- the float chain is `shares_status(fetch=False)` + Massive (no Yahoo call, no 429 marker).

Today's qualifiers join the listed set in memory, so a first dry run before any wet pass still reads them.
