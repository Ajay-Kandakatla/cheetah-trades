# Gajjala's tab — sources and the verified-rule set (2026-10-13)

The 📓 Playbook on Chart Maps → Gajjala's is built from ONE committed file:
`backend/chart_maps/gajjala/verified_rules.json`. Every rule in it has a status, at least one source, and (for the two
videos) a timestamp tied to its video id. This doc says where each source came from, how a status was assigned, and
which corrections the verification made to the session's own notes.

The file is **hand-maintained**: the one-off builder WP7 first generated it from (scratchpad, never in the repo) is
retired — it would revert later hand edits (the R5 quote's "slippage" clause was one). Edit the JSON directly; the
contract test is the guard. Re-run it (no network, no Mongo):

```bash
cd backend && .venv/bin/python -m pytest -q -p no:cacheprovider tests/test_gajjala_verified_rules.py
```

## How a status was assigned

- Each rule's `status_raw` is the verifier's code from STRATEGY_SPEC §1.3 verbatim (FH / MS / SS / CX / UN, † = HIS CALL).
- A mixed code (`FH† / SS†`, `MS / FH†`) is served at its **weaker** part — the file never claims more than the weakest
  piece of a combined rule. The one exception is a `CX` part that is filed as its own contradicted rule: `FH / CX`
  (HF4, Horizontal Fade frames) keeps FH for 5m/15m and carries the 30-minute disagreement in `contradiction`, because
  the 30-minute claim itself is rule T6. The file's `status_rule` line says the same.
- `his_call` is exactly the † mark.
- Every source reference says how it got there (`via`): `spec` = cited by §1.3; `first_hand_notes` = matched to a line of
  FIRST_HAND_ibd_webinar.md (timestamp and quote from there); `wp7` = attributed here, listed below.
- Quotes are verbatim from FIRST_HAND (auto-caption grammar), from §1.3, or from the fetched post text. GG's own word for the snap-back
  is served as "[reverses]" / "[reversal]" (the standing reversal rule); `[stop]` / `[stops]` are FIRST_HAND's own
  clarifications.
- Every quote names the reference that said it: `quote_src[i]` = `{key, ts}` or `{key, post_id}`, matching exactly one
  entry of the rule's `sources`. On a "his words" rule that entry must be first-hand, so a third-party line (Business
  Insider, F4VS) can never be shown as GG speaking. All 45 quotes in the file today are GG's (S8, S9 or his X posts).
- `numbers` on a rule with `used_by` is checked against constants.py: every number in it (ISO dates aside) must equal
  the value of one of the constants it names, and every constant whose provenance comment starts `# GG` (plus
  EMA_FAST / EMA_SLOW, re-exported with a `— GG` comment) must be named by some rule's `used_by`. A re-tune in
  constants.py therefore fails the test until the item says the same. Rules whose number is not what the code enforces
  carry `numbers: null` and keep the figure in their text (BF4: his "twice, thrice" / ~10× vs Ajay's 5× cap); U2 prints
  only the $0.10 the scanner uses, with the $0.50 history in its rule and `contradiction`; U3's +25% names
  SCAN_MIN_CHANGE_PCT (the ☀️ list takes only today's scanner qualifiers).

  his_call 68 — supplying the full set or accepting 107 is the main session's / Ajay's call). The "Who he is" and
  "What he avoids" Playbook sections have no topic here; the Playbook sources them from FIRST_HAND (9:45–12:00,
