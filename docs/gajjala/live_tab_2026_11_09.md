## What moves

| before | after (when the feed is live) |
|---|---|
| card price: the 30 s `POST /chart-maps/live` poll (≤ 30 s old) | streamed prints, at most one batch per second per board (about 1–2 s old) |

## The event: `gajjala.update` (one type, existing bus)

Published through `events.publish` (backend/events/bus.py). No new SSE endpoint. `SSE_HEADERS`, the six SSE
endpoints and `quote.update` are unchanged. Producer: `backend/chart_maps/gajjala/live_events.py`, called by the hub
(`backend/live_hub.py`, WP-A). Payload keys are fixed and pinned by a test (`QUOTES_KEYS`, `QUOTE_KEYS`, `PASS_KEYS`,
`LANE_KEYS`):

```
{"kind": "quotes", "variant": "gajjala" | "gajjala_1m" | "gajjala_audited",
 "quotes": {"SYM": {"price": 4.12, "as_of_epoch": 1792161440.0, "vs": {"kind": "...", "text": "..."} | null}}}
{"kind": "pass", "variant": "...", "pass_id": "2026-11-10|10:31", "finished_at_epoch": 1792161660.0}
{"kind": "lane", "day": "2026-11-10", "changed_at_epoch": 1792161660.0}
```

- `quotes`: per board variant (the board key, `variant.Variant.tab`), at most one batch every
  `GG_LIVE_QUOTE_BATCH_SEC = 1.0` (mine). It carries only symbols that had a new filtered print since that variant's
  last batch, and only for a variant whose cards are on screen (live interest). Latest print wins: an older print never
  replaces a newer one. Variants go out in ascending order, and symbols ascending inside a batch.
  - `as_of_epoch` = the SIP time of the print (`t_ms`), or the receive time when the feed sent none.
  - `vs` = the poll's own `live_card.live_vs(price, level, now_et)` with **that variant's** level. It is
    **injected**: `chart_maps/api.py` calls `live_events.set_vs_fn(LC.live_vs)` once at import and again at each
    stream registration. `live_events.py` never names the card module, so the 2026-10-21 import guard over
    `chart_maps/gajjala` holds. Because it is the same function object as the poll's, the words are equal for the same
    price, level and clock (pinned by a test). If nothing has been injected, `vs` is null; there is never a second
    formula. The 🚩 and 1-minute levels for one symbol never cross.
  - The print filter is the hub's ONE filter (`live_hub.PRINT_KINDS`, HIS CALL #2). Nothing here filters again.
- `pass`: a pointer change in `gajjala_passes` nudges `gajjala` **and** `gajjala_audited` (🧪 borrows 🚩's passes).
  `gajjala_1m_passes` nudges `gajjala_1m` **only**. The mapping comes from the store's own naming
  (`live_events.pass_variants`, via `GajjalaStore.physical`), never typed.
- `lane`: no symbol, qty, price or P&L key, by design (see delivery below).

## The poll asks for the stream

`POST /chart-maps/live` takes two optional body keys, `"stream": true` and `"variant": "<board key>"`. The route calls
`live_hub.register_interest(variant, symbols, levels)` **on the event loop, before** the `asyncio.to_thread(compose)`
read. The answer gains `"stream": {"on", "word", "state"}`:

- `word` and `state`: the pair the hub returns, which comes from `live_feed.state_word()`. When the hub gives no
  pair, the route calls `live_feed.state_word()` itself. `feed_state` never carries them; only `/live/feed-status`
  copies them in. State is one of `live | kicked | down | quiet | off`.
- If the hub is missing or raises, the answer is `on: false` with the feed's word. The poll still answers.

**Without `stream: true` (strict `True`) the answer is byte-identical to before.** A test holds the pre-change bytes,
captured before `api.py` was touched, for six bodies (plain, levels, `stream: false`, bad levels, 422, 413). The 413
and 422 refusals register nothing.

Judgement call: `state` is one key beyond §3.5's `{"on", "word"}`. Without it the board cannot tell "on, healthy"
from "on, kicked". The word prints only when the stream is degraded (below).

## The board (frontend)

- `hooks/useCardLive.ts`: the options `stream`, `variant` are added to the POST body only when `stream` is true. The
  body is otherwise exactly as before. The served `answer.stream` rides along.
- `hooks/useGgLive.ts`: one subscription to `gajjala.update` (the house `lib/eventBus`), filtered to the board's
  variant. It returns `{quotesEvt, passNudge, laneNudge}`:
  - Quotes fold newer-wins.
  - Nudges are coalesced over `GG_PASS_NUDGE_DEBOUNCE_MS = 500` (mine): two inside 100 ms become one.
  - With no `EventSource` (a test DOM), it stays idle.
- `lib/cardLive.ts` (pure):
  - `patchQuotes(answer, evt, nowEpoch)` replaces `now.price`, `now.as_of_epoch` and `vs` only when the stream's stamp
    is **newer**. It never touches the bar, the labels or the footer. A symbol not on the card does nothing.
  - `parseGgUpdate` and `mergeQuotesEvt` validate and fold the event.
  - `streamFeedWord` returns the served word only when degraded (`on` false, or a served `state` other than `live`).
- `components/GajjalaBoard.tsx`:
  - Sends `stream: true, variant: vkey` on the poll.
  - Splices the stream into the poll's state (`cardLive` = poll + stream), so the 2026-10-21 wiring and its contract
    pins read unchanged.
  - A `pass` nudge for this variant does one `setTick` (one GET) **and** restarts the served-cadence interval. The
    next cadence GET counts from the nudge, so there is no extra GET per cadence.
  - The served feed word prints right after the live footer, only when degraded, as its own item in the wrapping strip
    (`min-width: 0` + `.gg-line` = `overflow-wrap: anywhere`). On the phone (430 px) that adds no new row and no
    horizontal overflow.

## Bandwidth

Quote batches: ≤ 1/s × ≤ 80 symbols (`INTEREST_MAX`) × ~60 B. That is about **5 KB/s per variant on screen (~18 MB/h)**,
while some tab shows a 🚩 board (interest lives `INTEREST_TTL_SEC` = 60 s after the last poll). It is **zero** when
nobody is on a board. A hidden tab stops polling (`document.hidden`), so its interest expires within 60 s.

## Delivery: owner-only is NOT built (it needs a bus change)

Ajay asked for this setup **for the owner only**. The bus cannot do that today:

- `events/bus.py` keeps one anonymous queue per `/events` connection.
- `events/sse.py` fans every event out to every queue.
- No user identity is attached to a subscriber.

Owner-only delivery needs a user tag on the subscriber queue plus a per-event audience filter. That is a change to
`events/bus.py` / `events/sse.py` (and the six-SSE guard), which the main session owns. It was **not** made here.

Until then, `gajjala.update` goes to **every signed-in tab** (household users included). It carries only:

- public prices plus the served `vs` words (the same words the 🚩 board already serves to every reader), and
- data-free nudges: `pass` = a pass id + time; `lane` = a day + time. No symbol, qty, price or P&L (pinned by a NEGATIVE
  test).

A household tab not on a 🚩 board ignores the events (no handler), but its connection still carries the bytes.
